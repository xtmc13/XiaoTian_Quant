## 零、执行原则

1. **先证伪，再修。** 每个缺陷先留下能区分旧行为的失败检查；无法复现的（外部交易所）用接口契约 + 单测替身证明。
2. **先消除假成功，再统一撮合。** 账户动作返回 `success` 但没发生外部副作用，是最高优先级；撮合统一是结构性工程，单独排期。
3. **不改变已发布契约的默认语义。** 新增字段/接口向后兼容；确需改变默认行为时，用显式开关或明确错误码，不让旧调用方静默走新路径。
4. **不动无关代码。** 工作区已有的 42 个改动不纳入本轮 diff；每次提交按批次原子化。
5. **每批一个闸门。** `cargo test` → 目标包 `go test` → `npm run typecheck/test` → 手动入口验证；任一项失败不进入下一批。

## 二、批次 A：先止血（本轮执行）

### A1 修 Rust 市价单状态（对应 R-04）

- **现状**：`engine/src/matching.rs:100-107`，`is_market || filled >= quantity` 使空簿市价单返回 `Filled`。
- **改动**：
  - 删除 `is_market ||`，状态只由成交量决定：`filled >= quantity` → Filled；`filled > 0` → PartiallyFilled；否则按 `taker.status`（市价未成交为 Cancelled）。
  - 保留市价单未成交进 `Cancelled` 的既有分支。
- **测试**：
  - 空簿市价买单 → `Cancelled, filled=0`。
  - 半簿市价买单 → `PartiallyFilled`，`filled < quantity`。
  - 足额市价单 → `Filled`。
  - 限价单部分成交语义不变。
- **验收**：`cargo test` 全绿；新增 3 条回归。
- **风险**：低。Go 侧对 `Filled` 的假设需要同步检查（`matching.go` 回退实现是否同 Bug）。

### A2 下线假买币（对应 G-01 的一部分）

- **现状**：`gateway/internal/handler/account.go:100` `BuyCrypto` 注释即“simulates”，返回成功。
- **改动**：
  - 返回 `501 Not Implemented`，文案说明“应用内不代买，请走交易所法币入口”。
  - 路由保留（前端可能探测），但不再返回成功。
- **测试**：`POST /account/buy` → 501，响应无 `success:true`。
- **验收**：前端/接口探测不再得到成功。
- **风险**：低；若有用户依赖，会从“假成功”变为明确不可用。

### A3 划转接真（对应 G-01）

- **现状**：`handler/account.go:52-53` 注释“Simulate transfer”，只改 `binance_*` 内存余额；`TradingContractClassic.tsx:209` 有真实入口。
- **改动**：
  - `adapter/binance.go` 增加 `TransferAsset(from, to, asset string, amount float64) error`，走 `POST /sapi/v1/asset/transfer`，支持 `MAIN_UMFUTURE` / `UMFUTURE_MAIN` / `MAIN_FUNDING` / `FUNDING_MAIN` / `UMFUTURE_FUNDING` / `FUNDING_UMFUTURE`。
  - SAPI base URL 支持 `BINANCE_SAPI_REST_URL` 覆盖，便于 httptest。
  - `handler.Transfer` 改为：按 `portfolio` 账户前缀解析交易所（当前仅 `binance_*` 可解析；其他返回 501），调用 adapter；成功后刷新 portfolio（从交易所重新拉取），**不再手改内存**。
  - 凭证缺失 → 400；权限不足/交易所拒绝 → 502，原样带交易所错误。
- **测试**：
  - httptest 模拟 SAPI：成功 200 `{"status":"OK"}` → handler 200；`tranId` 存在。
  - 交易所返回 `{"code":-2010,"msg":"insufficient balance"}` → 502，内存余额不变。
  - 无凭证 → 400，不发生 HTTP 调用。
- **验收**：划转成功必须能在交易所侧查到；失败无本地余额变化。
- **风险**：中。需要 API Key 具备万向划转权限；错误文案必须可操作。

### A4 杠杆设置接真（对应 G-02 的入口部分）

- **现状**：`handler/contract.go:53-61` 空实现；`api.ts:2685` 只传 leverage，无 symbol/exchange。
- **改动**：

  - `handler.contract.go` 按交易所分派；OKX 直接下单带 `lever`，返回明确“下单时生效”；其他所 501。
  - `api.ts` 同步类型；前端调用点改为带 symbol（当前无调用点，只改类型与签名）。
- **测试**：httptest 验证签名参数含 `symbol/leverage`；成功 200；失败透传；缺 symbol 400。
- **验收**：设置后交易所查询杠杆值一致。
- **风险**：中。已有持仓时交易所可能拒绝调整；必须把错误透传给用户，不吞。

### A5 下单幂等键（对应 G-04）

- **测试**：同一订单 ID 生成稳定 ID；httptest 断言参数存在；模拟超时后查到已成交则不重发。
- **验收**：重复提交 100 次只产生 1 笔交易所订单。
- **风险**：中高。需要逐所字段与长度约束；先接 Binance/OKX/Bybit。

## 三、批次 B：行情与止损时效

### B1 收盘 K 线走 WS（对应 G-06 / R-07）

- 现状：`market/kline_feeder.go` 20 秒 REST 轮询；`exchange/binance_ws.go` 有 kline 流但未进策略总线。

- 验收：收盘后 ≤500ms 到策略；无重复 bar。

### B2 TP/SL 改 tick 驱动（对应 G-06）

- 现状：`handler/executor_tpsl.go:355` 5 秒 ticker。
- 改动：订阅 `TypeTick`，按 symbol 路由到状态机；ticker 仅做兜底（30s）。

- 验收：止损触发延迟 P99 < 200ms（本地回放）。
- 风险：中。共享状态需按 execID 加锁，避免并发双触发。

### B3 删模拟做市单 / 收进演示开关

- 验收：默认 Paper 无假单；演示模式显式开启。
- 风险：低。

### B4 滑点/手续费模型统一

- 现状：Paper 整单成交、回测 T+1 开盘、Rust 吃盘口，三套。
- 改动：新增 `internal/execution` 共享模型（`Fee`/`ApplySlippage`/`SplitFill`/`PlanLimitFill`）；Paper 交易所成交扣费、回测滑点与佣金、paper OMS 限价撮合全部走同一套公式。`PaperConfig` 增加 `partial_fill_rate`（默认 1.0，保持整单成交），paper OMS 部分成交时订单状态为 `PARTIALLY_FILLED` 且只在整单完成后撤订单簿；`fillOrderAndUpdatePortfolio` 支持可选 `fee`，现货买卖与合约开平都从计价币余额扣费。
- 验收：同一组行情/订单在 Paper 与回测两条 Go 路径上的费率、滑点、部分成交口径由同一模型计算；Rust 内核仍走自身订单簿，不在本轮统一。
- 风险：中。

### B 批已知边界

1. B1 的“重连补缺口”由 20 秒 REST 兜底完成，不是重连瞬间主动 REST 拉取；中间柱会按旧→新补发，但延迟最多一个兜底周期。
2. WS kline 订阅当前只增不减：策略释放后交易所流仍保留该 symbol+interval（不会产生重复事件，但订阅集合会缓慢增长）。
3. B2 的 tick 源依赖进程内事件总线；若 WS 断连，30 秒兜底仍会拉 REST 价格，但延迟回到兜底周期。
4. B4 只统一了 Go 侧 Paper 与回测；Rust 内核仍按自身订单簿成交，滑点体现在吃单深度而非参数化模型。Paper 的 `partial_fill_rate` 默认 1，未改默认行为；要模拟部分成交需显式配置。
5. 当前 `store/db.go` 已切换到 PostgreSQL（`DATABASE_URL`/`POSTGRES_*`），`internal/handler` 的 `TestMain` 没有本地 PG 会直接 `database not configured`。B4 的 handler 改动只做了编译验证，未跑 handler 单测；共享模型与 Paper/回测测试可独立运行。
